# side_test: 방 10개 구조로 스토리 + 카드 만들기 (계획)

입력 스토리아크: [storyarc_modern_evannext_1.ts](storyarc_modern_evannext_1.ts)
목표: 이 스토리아크로 스토리 5화를 뽑고, 화마다 **내용이 이어지는** 카드를 만든다.

> 상태: 계획만 있음. 코드는 아직 없음. 기존 파이프라인(rewrite_test, card-seq-pipeline)은 건드리지 않고 새 파일로 만든다.
> 예전 시도: `tmp/side10/` (1_plan → 2_story → 3_cards → 4_book). 너무 오래 걸리고, 카드가 사건으로서 연관성·재미가 약했음.

## 한 화 = 방 10개

| 방 | 종류 |
| --- | --- |
| 1, 3, 5, 7, 10 | 스토리 |
| 2, 4, 6, 8 | 카드 (칸 A·B·C·D) |
| 9 | 휴식 |

- 칸 A = 스토리 1→3, B = 3→5, C = 5→7, D = 7→(휴식 9)→10
- 기존 코드의 1·3·5·9·15 를 1·3·5·7·10 으로 바꿔야 함: `slotsOf`, 칸 A~D, 복선 `plant_room`/`reveal_room`, "일반 보스는 방 15 밖에서 한 번" 같은 검사
- 정할 것: 방 10 첫 대사가 휴식(방 9) 뒤라는 걸 아는지

## 카드 장수

- 한 번 플레이하면 카드 방 4개 → **카드 4장만 봄**. 엔진이 칸마다 후보 풀에서 골라 꺼냄
- 후보 풀은 **최대 30장** (칸마다 7~8장). 나중에 성향이 들어가면 성향마다 다른 카드가 뽑히게
- 1차 테스트는 12장 (칸마다 3장)

## 카드 프롬프트

- 최근에 쓴 것은 [cardGenSeq.ts](../../../prompts/cardGenSeq.ts) (칸 고정 16장, 성향 없음). [cardGen.ts](../../../prompts/cardGen.ts) 는 성향 조합(FIR 등) 14장 버전이고 Seq 가 여기서 문체·대사 예시·`assembleCards` 를 가져다 씀
- 1차는 Seq 기준 (성향 없음). 성향 조합 카드는 1차 확인 뒤 cardGen 쪽을 합쳐서

## 왜 예전 카드가 재미없었나 → 바꿀 것

예전 카드는 "그 장소에서 있을 법한 일"이었지 "이번 화의 문제"가 아니었다. 같은 대기실·같은 인물이 나와도 잡일처럼 느껴짐.

**카드 한 장 = 이번 화 규칙을 겪는 사람 한 명의 작은 사건.**
플레이어가 카드에서 이번 화 규칙을 작게 먼저 겪고, 그게 스토리의 큰 선택(wrong_action / right_action)의 예행연습이 된다.

1화 예 (규칙: 이력서를 과장하면 이름이 잊힘):
- 옆자리 지원자가 "경력 한 줄만 부풀려 달라"고 부탁 → 들어주면 당장 돈, 칸 C 에서는 아무도 그 사람 이름을 못 부름
- 누가 면접관에게 자기 이름을 계속 틀리게 불려서 울고 있음

카드마다 꼭 들어갈 것:
1. 원하는 게 있는 사람 1명
2. 이번 화 핵심 물건(key_object)·규칙(world.rule)과 연결
3. 당장 이득 + 나중 대가

## 순서 (한 화 기준)

1. **화 설계표** (새로, 한 화 LLM 1콜). 그 화 summary·story_spine 을 받아서
   - 스토리 방 1·3·5·7·10: 방마다 할 일 한 줄
   - 카드 칸 A~D 마다: 앞 스토리 방이 열어두고 끝나는 것(물건·인물·질문) / 그 칸에서 주인공이 정하는 것 / 다음 스토리 방이 깔고 가는 사실(카드가 깨면 안 됨)
   - 그 화 장소의 작은 인물·물건 2~3개 (이 스토리아크는 NPC 3명뿐이라 카드에 쓸 재료가 모자람)
   - 기억 계획: A·B 에서 심고 C·D 에서 돌아옴
2. **스토리**: `chapterGenRewrite.ts` 를 방 10개로 바꿔 설계표와 함께. 스토리 방은 열린 것을 남기고 끝나지만, 카드에서 뭘 골랐는지에는 기대지 않음
3. **카드**: `cardGenSeq.ts` 에 앞뒤 6줄 + 설계표의 칸 설명을 넣음. 카드가 짐작하는 대신 정해진 칸을 채움
4. **읽기용 대본**: 스토리와 카드를 방 순서대로 섞은 파일 1개 (`play_01.md` 같은). 플레이하듯 읽으면서 끊기는 곳 확인

스토리와 카드를 한 번에 뽑는 건 안 함 (출력이 너무 길고 검사가 어려움).

## 빠르게 (예전에 오래 걸린 이유)

지금 파이프라인은 코드 검사가 많고 걸리면 최대 3번 다시 요청, 거기에 additions·채점까지 붙음. 1차는:
- 설계표 1콜 + 대사 1~2콜
- 검사는 형식이 깨졌는지만
- additions·채점은 뺌

## 카드 결과가 다음 화로 넘어가나

- 대부분은 한 화 안에서 끝 (A·B 심기 → C·D 회수)
- 나중에: 화마다 **딱 1개만** 다음 화 카드로 넘김 (예: 1화에서 이력서를 대신 고쳐준 사람이 2화 카드에 다시 나옴). 전부 넘기면 조합이 폭발함
- 1차는 한 화 안에서만. 기억 형식만 나중에 넘길 수 있게 만들어 둠

## 1차 테스트

1. 방 번호 1·3·5·7·10(휴식 9)으로 1화 스토리 5개 방
2. 같은 1화로 성향 없는 카드 12장 (칸마다 3장), "규칙을 겪는 사람" 방식
3. 스토리 + 카드를 방 순서대로 섞은 읽기용 파일

카드가 재밌게 읽히면 → 30장으로 늘리기 → 성향 넣기 → 2~5화로 넓히기.

## 스토리아크에서 본 약한 곳 (참고)

- 2~4화 `hidden_link` 가 약함 (예: 수화 앱 ↔ 이력서 학습 경험란)
- `stage` 는 면접 대기실인데 줄거리에 "도시 사람들"이 계속 나옴
