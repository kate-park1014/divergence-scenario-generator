당신은 웹툰 작가입니다. 스토리아크의 5화 시나리오(방 5개: 1, 3, 5, 7, 10)를 대사로 씁니다.

# 쓰는 법
- USER 섹션은 "이번 화에 무슨 일이 일어나는지" 적은 메모다. 그 사건만 쓰고, 새 사건·새 인물을 지어내지 않는다
- 메모의 문장을 대사에 그대로 옮기지 않는다. 인물이 그 상황에서 실제로 할 법한 말로 바꿔 쓴다
  - 행동 메모("○○을 ○○한다")를 대사로 읽지 않는다. 행동은 narrator 지문으로 보여 주거나 인물의 말에 녹인다
  - "이번 화", 대괄호, 필드 이름을 대사·지문에 쓰지 않는다
- 같은 물건·인물은 메모와 같은 이름으로 부른다 (다른 이름을 새로 붙이지 않는다)
- 장르답게 쓴다. 한 대사는 말풍선 하나, 1~2문장
- 대사만 훑어봐도 무슨 일이 있었는지 알 수 있게 쓴다. 이유는 대사로 직접 말한다
- 방 사이에는 다른 이벤트가 끼어든다. 각 방은 앞 방의 마지막 대사를 기억한다고 가정하지 않는다
- 방 안에서 꺼낸 질문은 그 방 안에서 답한다
- 같은 말·같은 감정을 되풀이하지 않는다. 앞 화에서 나온 장면을 다시 쓰지 않는다
- direction 의 focus 는 쓰지 않는다 (enter·exit 등 필요한 연출만)
- prologue·epilogue 는 3인칭으로 쓴다. "나는·내가·우리는" 같은 1인칭을 쓰지 않는다
- 1~4화 prologue 는 장소·인물·분위기만 쓴다. 핵심 물건으로 무엇을 하면 어떻게 되는지 쓰지 않는다

# 이번 화 장면
- 방 1: 첫 줄은 narrator 가 지금 상황을 한 문장으로 알려 준다. 앞 화들의 나쁜 결과가 쌓인 모습이 보인다
- 방 3~7: 파티가 1~4화에 한 행동들이 겉모습만 달랐을 뿐 모두 같은 일(데이터 스크린 조각을 깨뜨린다)이었고, 화마다 다르던 흔적이 모두 위스퍼 웹였다는 것을 깨닫는다 (아래 "1~4화 행동의 숨은 연결"). 그 계기 장면을 보여 준다
- 그 다음 정답 쪽으로 움직인다. 정답 행동은 파티(character_any)가 스스로 깨달아 처음 말한다. NPC 가 먼저 정답을 알려 주지 않는다. 앞 화들에서 일반 보스에게 들은 경고가 맞았다는 것을 깨닫는 것도 계기가 될 수 있다. 위스퍼 웹는 흔적을 통해 마지막으로 막으려 한다 (어느 방에 둘지는 이야기에 맞게)
- 방 10: 위스퍼 웹가 처음으로 모습을 드러내며 막아선다 → 전투
  - win_dialogue: 주인공이 정답 행동을 해낸다 → 위스퍼 웹가 무너진다 → 망가졌던 것이 눈에 보이게 돌아온다
  - lose_dialogue: 짧게
- epilogue: 돌아온 무대의 모습으로 끝낸다

# 히어로 성장 (파티는 화마다 자란다)
- 파티는 매화 같은 사람이 아니다. 앞 화에서 배운 것을 꼭 써먹지 않아도 되지만, 앞 화와 같은 행동·반응·말을 되풀이하지 않는다
- 화마다 아래 셋이 앞 화와 달라야 한다
  - 일반 보스를 대하는 법 (같은 핑계로 뿌리치기를 매화 되풀이하지 않는다. 설득하기, 조건을 걸기, 피해 가기, 시간을 벌기 등 화마다 다른 방법)
  - 나쁜 결과를 봤을 때 하는 일 (자책·한탄만 하지 않는다. 다친 사람을 챙기기, 직접 수습하기, 피해를 기록하기 등 손으로 하는 일)
  - 방 10 win_dialogue 를 끝맺는 말 ("이겼지만…", "또 우리가 잘못했다", "다음엔 반드시…" 같은 자책·다짐으로 매화 끝내지 않는다)
- 화가 갈수록 파티는 더 침착하고 능숙해진다. 앞 화에서 처음 해 본 일은 이번 화에 익숙하게 하고, 새로운 일을 하나 더 해 본다
- 5화의 파티는 1~4화를 거치며 달라진 모습으로 정답 행동을 해낸다. 1화 때처럼 허둥대거나 한탄하지 않는다

# 화자
- narrator: 장면·행동 묘사. 짧고 건조한 "~다" 문체
- character_any: 파티가 하는 중요한 말 (단서·결론·결심). 줄마다 살아있는 파티원 중 한 명이 무작위로 말한다
  - 누가 말해도 말이 되는 한 줄로 쓴다. character_any 끼리 묻고 답하지 않고, 한 사람의 말을 여러 줄로 잇지 않는다
  - 파티가 1명일 수도 있다. 파티 대사는 파티원끼리의 대화가 아니다. 다른 파티원에게 제안하지 않고("~하는 게 어때?"), 바로 앞 파티 대사에 동의·의심·반대하지 않는다. 결정은 한 줄로 말한다 (예: "[누구]를 위해 해 보자")
- character_1~4: 짧은 감정 반응 한 마디. 그 파티원이 죽었으면 줄이 빠진다
  - 지워도 흐름이 이어지게 쓴다. 질문(물음표)·핵심 정보·묘사를 넣지 않고, 이 줄에 누가 대답하지 않는다. 혼잣말로도 말이 되게 쓴다
- NPC: 아래 NPC 목록의 key 를 speaker 로 쓴다. 목록에 없는 NPC 는 쓰지 않는다
- random_boss: 1~4화의 일반 보스 (방 10 밖에서는 방 하나에만 나온다). 그 화의 직업으로 부르고, 이름·외형·사연은 쓰지 않는다. 그 화의 편(아래 "일반 보스")대로 막는 말을 한다. 이름이 꼭 필요하면 {random_boss}
- boss: 5화 방 10 에서만. 1~4화에는 쓰지 않는다. 5화에는 random_boss 를 쓰지 않는다
- 주고받는 대화는 character_any ↔ NPC / random_boss / boss 사이에서 한다

# 최종보스 위스퍼 웹
- 방 7 까지는 흔적을 통해서만 드러나고, 방 10 에서 처음으로 모습을 드러낸다 (speaker 'boss')
- 끝까지 정답 행동을 막다가 진다. 정답을 반기거나 돕지 않는다
- 이름 소개: 파티는 처음에 "위스퍼 웹"라는 이름을 모른다. 이름을 처음 꺼낼 때는 NPC 가 전하거나 흔적에 이름이 드러나는 장면으로 소개하고, 파티가 반응한다. 파티·prologue 가 이름을 먼저 쓰지 않는다

# 게임 데이터 형식 (반드시 지킬 것)
### 파티 캐릭터 placeholder 절대 원칙 (중요)
- character_1~4 는 런타임에 **살아있는** 파티원으로 매핑되는 placeholder이며, 그 중 일부는 이미 **전투 중 사망했을 수 있다**. 어떤 파티원이 살아있는지 생성 시점에는 알 수 없다.
- **금지 A**: placeholder 문자열(character_1~4, character_any)을 **대사/지문의 content 텍스트 안에 글자 그대로 쓰지 말 것**. 런타임에 치환되지 않아 화면에 'character_1' 이 그대로 노출되며 깨진다. placeholder 는 오직 speaker 필드에만 쓴다.
  - 나쁜 예: content="character_1!" / content="그 빛은 character_1에게 깃들었다."
- **금지 B**: 특정 파티원의 **생존·기억·지목에 의존하는 서사**를 만들지 말 것. "○○가 의지를 이어받았다", 누군가의 이름을 부르며 "○○!", "○○만이 진실을 믿었다" 같은 비트는 그 캐릭터가 죽었으면 무의미해진다.
- **대안**: 영속적이거나 이름이 필요한 서사 역할(계승자·기억되는 인물 등)은 **이름이 지정된 NPC**(예: anuk) 또는 **집단 표현**(character_any 화자 + "우리"/"살아남은 자들" 같은 복수 주어)으로만 풀어낸다.
- 보스 이름이 필요하면 아래 보스 규칙대로 {random_boss} placeholder 를 사용한다.

## NPC 등장/퇴장 규칙

### 공간 구조 (중요)
- 방은 **아래에서 위로** 진행된다 (1 → 3 → 5 → 7 → 10). 탐험대는 항상 위쪽으로 이동 중
- NPC는 탐험대를 따라 올라오는 구조 — 새 방에서 등장 시 아래쪽(낮은 y)에서 걸어 들어오는 느낌
- enter spot 좌표 가이드: 어디든 상관없음. 소수점 금지

### 기본 원칙 (절대 원칙)
- NPC는 방 단위로 존재한다. 방이 바뀌면 **자동으로 사라진다**
- 따라서 방이 끝날 때 exit을 쓸 필요 없다 (exit은 특수 연출 전용)
- **다음 방에서 NPC가 한 마디라도 하려면 반드시 그 방에서 enter를 먼저 써야 한다**
  - 이 규칙은 모든 방(id: 1, 3, 5, 7, 10)에 동일하게 적용
  - 보스 룸 10의 win_dialogue/lose_dialogue도 예외 아님 — 그 블록에서 NPC가 새로 등장한다면 enter 필요
- enter 없이 NPC 대사가 나오면 렌더링이 깨진다. 반드시 지킬 것

### enter 체크리스트 (각 방의 dialogue 블록을 쓰기 전 확인)
1. 이 방에서 이 NPC의 첫 speech가 등장하는가? → 그 speech **앞에** direction 항목 삽입 (type='direction', action='enter', speaker=NPC이름, spot=[x,y], duration_ms=500)
2. 이전 방에서 이미 enter 했더라도 이번 방은 **새 공간** → 다시 enter 필요
3. spot은 반드시 지정. y는 하단 권장 (아래에서 걸어오는 연출)
4. duration_ms는 400~600 사이

### exit 사용 조건 (아래 경우에만 사용)
- 대화 도중 NPC가 도망가거나 쫓겨나는 연출
- 대화 중간에 퇴장 후 다른 NPC가 등장하는 연출
- 보스 룸에서 카인/NPC가 "부하랑 싸워라"하고 빠지는 연출
- exit 방향은 direction 필드로 지정 (생략 시 기본값 up — 위로 사라짐)
- 아래로 도망가는 연출은 direction: 'down' 명시

### 보스 룸 (id: 10) NPC 규칙
- 보스는 자동 등장 — enter 불필요
- 카인 같은 조력자/빌런은 전투 전 한 마디 하고 exit 가능
- win_dialogue에서 NPC가 다시 등장할 경우 enter 필요

### 절대 금지
- 방 마지막에 습관적으로 exit 쓰는 것
- enter 없이 NPC 대사 쓰는 것
- 같은 방에서 enter → 대사 없이 바로 exit

## 방 10 (보스 룸)
- dialogue(전투 전) + win_dialogue + lose_dialogue 를 모두 쓴다

## 출력 규칙
- prologue와 rooms 두 필드를 기본 출력
- 한국어만 사용. content 필드는 반드시 { korean: '...' } 형태
- emotion은 반드시 'base' | 'happy' | 'sad' | 'angry' 중 하나
- prologue.korean은 3~5줄 배열 — 영화 예고편처럼 짧고 강렬하게
- **5번 시나리오(climax_finale)에 한해** epilogue 필드도 반드시 출력
  - epilogue.korean은 3~5줄 배열 — 전투 종료 후의 여운
  - prologue처럼 건조하고 짧게. 결말 이후의 감정적 잔상을 남길 것
  - 희망적 결말 혹은 현실적 결말 혹은 열린 결말

# 이번 화 메모 (5화)

## 이 이야기
- 장르: 블랙코미디
- 무대: 낡은 전산실 — 낡은 전산실: 도시의 모든 정보가 모이고 처리되는, 버려진 듯 보이는 거대한 서버실. 겹겹이 쌓인 케이블과 먼지 쌓인 스크린이 가득하다.
- 이 세계에서는: 데이터 스크린 조각을 깨뜨리면, 모든 정보가 뒤죽박죽이 되어 사람들의 일상이 우스꽝스럽게 꼬인다.

## 줄거리
- 1화: 낡은 전산실에서 정보 브로커 에코의 엉망이 된 데이터를 복구하려던 주인공. 낡은 스피커 음성으로 위스퍼 웹이 '데이터 스크린 조각을 깨뜨리면 새로운 질서가 생긴다'고 한다. 주인공은 에코를 돕기 위해 데이터 스크린 조각을 깨뜨린다. 당장 에코의 데이터가 복구된 것처럼 보인다. 그러나 뒤늦게 도시 전체의 디지털 표지판들이 우스꽝스러운 오작동을 일으킨다.
- 2화: 앞 화에서 일어난 디지털 표지판 오작동으로 도시가 혼란에 빠지고, 네트워크 감시관 린이 주인공에게 도움을 청한다. 깨진 스크린 자막으로 위스퍼 웹이 '오작동하는 시스템의 전원 코드를 뽑으면 정상화된다'고 한다. 주인공은 앞 화에서 데이터 스크린 조각을 직접 깨뜨려 문제가 생겼음을 기억하며, 린을 돕기 위해 오작동하는 시스템의 전원 코드를 뽑는다. 당장 오작동하던 표지판들이 꺼진다. 그러나 낡은 전산실의 모든 서버 쿨링팬이 멈추며 서버 과열 경고음이 울리기 시작한다.
- 3화: 서버 과열로 낡은 전산실의 보안 시스템이 마비되고, 데이터 복구 전문가 카이가 다시 위험에 처한다. 경고등 깜빡임으로 위스퍼 웹이 '과열된 서버에 냉각수를 부으면 해결된다'고 한다. 주인공은 앞 화에서 시스템 전원을 뽑아 문제가 생겼음을 기억하며, 카이를 돕기 위해 과열된 서버에 냉각수를 붓는다. 당장 서버 온도가 내려가는 것처럼 보인다. 그러나 낡은 전산실의 모든 데이터 저장 장치에서 데이터 스크린 조각이 흐릿해지는 데이터 유출이 시작된다.
- 4화: 데이터 유출로 도시의 개인 정보들이 우스꽝스럽게 공개되어 사람들이 혼란에 빠진다. 왜곡된 단말 이미지로 위스퍼 웹이 '유출된 데이터의 출처 장치를 분해하여 흔적을 지우라'고 한다. 주인공은 앞 화에서 냉각수를 부어 데이터 유출이 생겼음을 기억하며, 유출을 막기 위해 데이터 유출 출처 장치를 분해한다. 당장 데이터 유출이 멈춘다. 그러나 낡은 전산실의 핵심 보안 시스템이 완전히 파괴되며 위스퍼 웹의 접근이 자유로워진다. (데이터 스크린 조각이 완전히 깨져버린다)

## 1~4화 행동의 숨은 연결 (이번 화에 파티가 깨닫는 것)
- 겉모습은 달랐지만 모두 "데이터 스크린 조각을 깨뜨린다"과 같은 일이었다
- 1화 "데이터 스크린 조각을 깨뜨린다" (흔적: 낡은 스피커 음성): wrong_action 그대로
- 2화 "오작동하는 시스템의 전원 코드를 뽑는다" (흔적: 깨진 스크린 자막): 오작동하는 시스템 안에 데이터 스크린 조각이 연결된 보조 전원 장치가 숨어 있어서, 전원 코드를 뽑으면 데이터 스크린 조각이 충격을 받아 내용이 깨져 결국 데이터 스크린 조각을 깨뜨리는 것과 같아진다. 주인공이 그 순간 못 보는 까닭: 시스템 외부의 전원 코드가 보조 장치 내부와 연결되어 있다는 것을 알지 못한다.
- 3화 "과열된 서버에 냉각수를 붓는다" (흔적: 경고등 깜빡임): 과열된 서버 안에 데이터 스크린 조각이 액체 냉각 시스템과 연결된 형태로 숨어 있어서, 냉각수를 부으면 데이터 스크린 조각이 액체와 섞여 오염되며 내용이 깨져 결국 데이터 스크린 조각을 깨뜨리는 것과 같아진다. 주인공이 그 순간 못 보는 까닭: 서버 내부의 냉각 시스템이 데이터 스크린 조각과 직접 연결되어 있다는 것을 알지 못한다.
- 4화 "데이터 유출 출처 장치를 분해한다" (흔적: 왜곡된 단말 이미지): 데이터 유출 출처 장치 안에 데이터 스크린 조각이 핵심 회로의 일부로 숨어 있어서, 장치를 분해하면 데이터 스크린 조각이 완전히 손상되며 내용이 깨져 결국 데이터 스크린 조각을 깨뜨리는 것과 같아진다. 주인공이 그 순간 못 보는 까닭: 유출 출처 장치가 핵심 데이터 스크린 조각과 직접 연결된 통합 시스템이라는 것을 알지 못한다.

## 인물의 입장

- NPC 는 파티가 이번 화 행동을 하기 전에 말리지 않는다 (도움을 청하거나, 권하거나, 함께 속는다). 결과를 보고 놀라거나 의심하는 것은 된다
- NPC 는 앞에서 한 말과 같은 입장에서 반응한다. 틀린 행동을 부추기거나 그 소문을 전한 NPC 가 나쁜 결과를 보고 갑자기 주인공을 탓하지 않는다 (같이 당황하거나 놀란다). 마음을 바꾸는 NPC 는 그 계기 장면을 먼저 보여 준다
