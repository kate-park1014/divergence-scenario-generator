# 5화 설계표 — 광기의 데이터 폭주

- 장소: 중앙 제어실 / 주 NPC: 에코 / 주인공 행동: **데이터 스크린 조각을 맞춘다** / 흔적: 흔적 / 최종보스: 위스퍼 웹

## 스토리 방
- **방 1**: 중앙 제어실에 들어서자 엉망이 된 개인 정보와 뒤죽박죽인 데이터 흐름이 가득 차 있고, 에코가 정보 혼선으로 곤란해하고 있다. 흔적이 나타나 해결책으로 데이터 스크린 조각을 깨뜨리라고 권하지만 파티는 아직 움직이지 않는다.
- **방 3**: 파티는 제어실 한쪽에서 오작동하는 시스템의 전원 코드가 보조 전원 장치 내부의 데이터 스크린 조각과 직접 연결된 구조를 발견한다. 이를 통해 과거에 전원 코드를 뽑거나 냉각수를 붓던 일들이 결국 데이터 스크린 조각을 깨뜨리는 일과 같았음을 깨닫는다.
- **방 5**: 파티는 데이터 스크린 조각을 깨뜨리는 대신 조각을 맞춰야 한다는 정답 행동을 스스로 깨닫고 처음으로 말한다. 흔적이 나타나 이를 강하게 막아서며 파티의 결정을 방해하려 한다.
- **방 7**: 파티가 데이터 스크린 조각을 맞추기 시작하자 주변의 디지털 표지판 일부가 정상으로 돌아오는 작은 효과가 나타난다. 에코가 통신을 통해 이 모든 혼란을 조장한 흔적의 주인이 위스퍼 웹이라는 사실을 알려준다.
- **방 10**: 위스퍼 웹이 홀로그램 형태로 모습을 드러내며 모든 정보는 깨져야 한다고 외치며 파티의 정답 행동을 막아선다. 전투에서 승리한 파티가 데이터 스크린 조각을 완전히 맞추자, 위스퍼 웹은 데이터 파편으로 무너지고 엉망이었던 도시의 시스템이 원래대로 돌아온다.

## 카드 칸
- **칸 A**
  - 열린 것: 에코가 겪는 혼선과 흔적이 권하는 '데이터 스크린 조각을 깨뜨리는' 해결책.
  - 정하는 것: 데이터 엉킴으로 고통받는 사람의 무리한 파괴 요구를 들어줄지 말지 정한다.
  - 깨면 안 되는 사실: 주인공이 아직 과거 행동들의 진짜 의미를 눈치채지 못했다는 점.
- **칸 B**
  - 열린 것: 과거의 잘못된 행동들이 결국 데이터 조각을 깨뜨리는 일이었음을 보여주는 장치 구조.
  - 정하는 것: 잘못된 방식임을 알게 되었음에도 당장의 위기를 넘기기 위해 다시 틀린 행동을 하려는 사람을 어떻게 할지 정한다.
  - 깨면 안 되는 사실: 파티가 아직 정답 행동을 입 밖으로 꺼내지 않았다는 점.
- **칸 C**
  - 열린 것: 파티가 스스로 정답 행동을 깨닫고 흔적과 대립하기 시작한 상황.
  - 정하는 것: 정답 행동의 예행연습으로, 작은 데이터 조각을 먼저 맞춰볼지 아니면 포기하고 다시 깨뜨릴지 정한다.
  - 깨면 안 되는 사실: 흔적의 주인의 진짜 이름이 아직 밝혀지지 않았다는 점.
- **칸 D**
  - 열린 것: 흔적의 주인의 이름이 밝혀지고 정답 행동의 작은 효과가 나타나기 시작한 상황.
  - 정하는 것: 흔적의 주인이 방해할 것을 직감한 상황에서 정답 행동을 계속 밀어붙일지 망설일지 정한다.
  - 깨면 안 되는 사실: 흔적의 주인이 아직 직접 모습을 드러내지 않았다는 점.

## 장소의 작은 인물·물건
- `tech_worker` 제어실 기술자 (person): 엉망이 된 개인 정보 때문에 권한을 잃어버려 당장 통제판을 부수고 싶어 한다.
- `apprentice` 수습 오퍼레이터 (person): 복잡한 복구 작업 대신 데이터를 폐기해 당장의 업무를 끝내고 싶어 한다.
- `data_terminal` 임시 데이터 단말기 (object): 깨진 데이터 조각을 임시로 모아두는 장치로, 잘못 건드리면 정보가 더 꼬인다.

## 기억 계획
- **A → C** (tech_worker): 권한 복구가 안 되니 당장 눈앞의 통제판을 물리적으로 부숴버리자고 요구한다.
  - easy: 통제판을 부수게 두어 당장 닫힌 문을 쉽게 열고 지나간다. / hard: 부수지 못하게 막고 수동으로 암호를 해독하느라 시간을 지체하며 고생한다.
  - 돌아옴: 통제판을 부수게 둔 경우 데이터 스크린 조각이 깨지는 효과가 발생해 기술자의 신분 데이터가 완전히 소거된다. 막은 경우 온전한 통제판 덕분에 기술자가 작은 데이터 조각 맞추기를 도와준다.
- **B → D** (apprentice): 복구가 귀찮다며 오작동하는 시스템의 전원 코드를 뽑아버리자고 요구한다.
  - easy: 코드를 뽑게 냅둬서 시끄러운 경고음을 끄고 당장의 편의를 얻는다. / hard: 코드를 뽑지 못하게 막고 복잡한 시스템 내부를 하나하나 점검한다.
  - 돌아옴: 코드를 뽑게 둔 경우 충격으로 데이터가 더 파괴되어 오퍼레이터가 오작동하는 문 안에 갇혀버린다. 막은 경우 온전한 시스템 덕분에 곧 다가올 거대한 방해를 뚫고 갈 작은 동력을 얻는다.
