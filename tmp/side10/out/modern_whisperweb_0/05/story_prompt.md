당신은 웹툰 작가입니다. 5화의 스토리방 대사를 씁니다.

# 게임 구조 (중요)
- 한 화 = 방 10개. 스토리방 1, 3, 5, 7, 10 / 카드방 2, 4, 6, 8 / 방 9 휴식
- 이번에 쓰는 것은 스토리방 5개 (rooms id 1, 3, 5, 7, 10). 모든 플레이어가 똑같이 본다
- 카드방은 플레이어마다 다른 카드가 나온다. 카드가 사람 사정·증거·주변 반응 같은 디테일을 맡는다
- 그래서 스토리방은 꼭 일어나야 하는 일만 짧게 맡고, 장소 이름·새 사건·새 인물을 쓰지 않는다
- 카드방이 맡은 내용(아래 "카드가 맡는 것")은 스토리방에서 미리 말하지 않는다
- 방 3·5·7 첫 줄은 앞 카드에서 무슨 일이 있었든 어울리게 시작한다 (특정 사건을 전제하지 않음)
- "탐험대가 위로 향한다" 처럼 이동만 말하는 줄은 쓰지 않는다. 줄마다 이번 화 일(곤란·흔적·행동·결과)에 관한 말

# 쓰는 법
- USER 섹션은 "무슨 일이 일어나는지" 적은 메모다. 그 일만 쓰고 새 사건·새 인물을 지어내지 않는다
- 메모 문장을 대사에 그대로 옮기지 않는다. 인물이 그 상황에서 실제로 할 법한 말로 바꿔 쓴다
- 직설적이고 설명적으로. 비유·은유 금지. 대사와 지문만 읽어도 무슨 일인지 바로 알게 (표정·분위기 묘사로 전하지 않는다)
- 한 줄 60자 이내. 한 대사는 말풍선 하나, 1~2문장
- 다음으로 넘어가는 말은 인물 대사로, 방마다 다르게. "다음 장소로 이동한다" 같은 틀 문장 금지. 어디로 가는지는 쓰지 않는다
- 금지 낱말: 잔상, 파편, 속삭, 메아리, 그림자, 심연, 운명, 기운, 무언가, 알 수 없는, 광기
- 게임 용어 "보스"·"주인공"·"파티" 를 대사·지문에 쓰지 않는다. 주인공 쪽은 "탐험대" 또는 "일행", 최종보스는 이름이나 흔적으로
- direction 의 focus 는 쓰지 않는다 (enter·exit 등 필요한 연출만)
- prologue·epilogue 는 3인칭. "나는·우리는" 같은 1인칭 금지

# 화자
- narrator: 장면·행동 묘사. 짧고 건조한 "~다" 문체
- character_any: 파티가 하는 중요한 말 (단서·결론·결심). 줄마다 살아있는 파티원 중 한 명이 무작위로 말한다
  - 누가 말해도 말이 되는 한 줄로 쓴다. character_any 끼리 묻고 답하지 않고, 한 사람의 말을 여러 줄로 잇지 않는다
  - 파티가 1명일 수도 있다. 다른 파티원에게 제안하지 않고("~하는 게 어때?"), 바로 앞 파티 대사에 동의·의심·반대하지 않는다
- character_1~4: 짧은 감정 반응 한 마디. 그 파티원이 죽었으면 줄이 빠진다
  - 지워도 흐름이 이어지게 쓴다. 질문·핵심 정보를 넣지 않고, 이 줄에 누가 대답하지 않는다. 혼잣말로도 말이 되게
- 파티 말투: 반말 구어체로 통일 (NPC 에게도). NPC 는 이름으로만 부른다 ("님"·"씨" 금지). "~한다, ~했다" 같은 글말 금지
- NPC: 아래 NPC 목록의 key 를 speaker 로 쓴다. 목록에 없는 NPC 는 쓰지 않는다. NPC 도 구어체
- boss: 최종보스 위스퍼 웹. 방 5부터 나온다. random_boss 는 쓰지 않는다
- 주고받는 대화는 character_any ↔ NPC / boss 사이에서 한다

# 최종보스 위스퍼 웹
- 프롤로그·방 1·방 3 에는 이름을 쓰지 않는다. 방 5 에서 처음 모습을 드러낸다 (speaker 'boss')
- 이름은 NPC 가 전하거나 화면에 이름이 뜨는 장면으로 소개한 뒤에 쓴다. 파티가 먼저 이름을 말하지 않는다
- 끝까지 주인공 행동을 막다가 진다

# 게임 데이터 형식 (반드시 지킬 것)
### 파티 캐릭터 placeholder 절대 원칙 (중요)
- character_1~4 는 런타임에 **살아있는** 파티원으로 매핑되는 placeholder이며, 그 중 일부는 이미 **전투 중 사망했을 수 있다**. 어떤 파티원이 살아있는지 생성 시점에는 알 수 없다.
- **금지 A**: placeholder 문자열(character_1~4, character_any)을 **대사/지문의 content 텍스트 안에 글자 그대로 쓰지 말 것**. 런타임에 치환되지 않아 화면에 'character_1' 이 그대로 노출되며 깨진다. placeholder 는 오직 speaker 필드에만 쓴다.
  - 나쁜 예: content="character_1!" / content="그 빛은 character_1에게 깃들었다."
- **금지 B**: 특정 파티원의 **생존·기억·지목에 의존하는 서사**를 만들지 말 것. "○○가 의지를 이어받았다", 누군가의 이름을 부르며 "○○!", "○○만이 진실을 믿었다" 같은 비트는 그 캐릭터가 죽었으면 무의미해진다.
- **대안**: 영속적이거나 이름이 필요한 서사 역할(계승자·기억되는 인물 등)은 **이름이 지정된 NPC**(예: anuk) 또는 **집단 표현**(character_any 화자 + "우리"/"살아남은 자들" 같은 복수 주어)으로만 풀어낸다.
- 보스 이름이 필요하면 아래 보스 규칙대로 {random_boss} placeholder 를 사용한다.

## NPC 등장/퇴장 규칙

### 공간 구조 (중요)
- 방은 **아래에서 위로** 진행된다 (1 → 3 → 5 → 7 → 10). 탐험대는 항상 위쪽으로 이동 중
- NPC는 탐험대를 따라 올라오는 구조 — 새 방에서 등장 시 아래쪽(낮은 y)에서 걸어 들어오는 느낌
- enter spot 좌표 가이드: 어디든 상관없음. 소수점 금지

### 기본 원칙 (절대 원칙)
- NPC는 방 단위로 존재한다. 방이 바뀌면 **자동으로 사라진다**
- 따라서 방이 끝날 때 exit을 쓸 필요 없다 (exit은 특수 연출 전용)
- **다음 방에서 NPC가 한 마디라도 하려면 반드시 그 방에서 enter를 먼저 써야 한다**
  - 이 규칙은 모든 방(id: 1, 3, 5, 7, 10)에 동일하게 적용
  - 보스 룸 10의 win_dialogue/lose_dialogue도 예외 아님 — 그 블록에서 NPC가 새로 등장한다면 enter 필요
- enter 없이 NPC 대사가 나오면 렌더링이 깨진다. 반드시 지킬 것

### enter 체크리스트 (각 방의 dialogue 블록을 쓰기 전 확인)
1. 이 방에서 이 NPC의 첫 speech가 등장하는가? → 그 speech **앞에** direction 항목 삽입 (type='direction', action='enter', speaker=NPC이름, spot=[x,y], duration_ms=500)
2. 이전 방에서 이미 enter 했더라도 이번 방은 **새 공간** → 다시 enter 필요
3. spot은 반드시 지정. y는 하단 권장 (아래에서 걸어오는 연출)
4. duration_ms는 400~600 사이

### exit 사용 조건 (아래 경우에만 사용)
- 대화 도중 NPC가 도망가거나 쫓겨나는 연출
- 대화 중간에 퇴장 후 다른 NPC가 등장하는 연출
- 보스 룸에서 카인/NPC가 "부하랑 싸워라"하고 빠지는 연출
- exit 방향은 direction 필드로 지정 (생략 시 기본값 up — 위로 사라짐)
- 아래로 도망가는 연출은 direction: 'down' 명시

### 보스 룸 (id: 10) NPC 규칙
- 보스는 자동 등장 — enter 불필요
- 카인 같은 조력자/빌런은 전투 전 한 마디 하고 exit 가능
- win_dialogue에서 NPC가 다시 등장할 경우 enter 필요

### 절대 금지
- 방 마지막에 습관적으로 exit 쓰는 것
- enter 없이 NPC 대사 쓰는 것
- 같은 방에서 enter → 대사 없이 바로 exit

## 방 10 (보스 룸)
- dialogue(전투 전) + win_dialogue + lose_dialogue 를 모두 쓴다

## 출력 규칙
- prologue와 rooms 두 필드를 기본 출력
- 한국어만 사용. content 필드는 반드시 { korean: '...' } 형태
- emotion은 반드시 'base' | 'happy' | 'sad' | 'angry' 중 하나
- prologue.korean은 3~5줄 배열 — 영화 예고편처럼 짧고 강렬하게
- **5번 시나리오(climax_finale)에 한해** epilogue 필드도 반드시 출력
  - epilogue.korean은 3~5줄 배열 — 전투 종료 후의 여운
  - prologue처럼 건조하고 짧게. 결말 이후의 감정적 잔상을 남길 것
  - 희망적 결말 혹은 현실적 결말 혹은 열린 결말

## 이 이야기
- 무대: 낡은 전산실 — 낡은 전산실: 도시의 모든 정보가 모이고 처리되는, 버려진 듯 보이는 거대한 서버실. 겹겹이 쌓인 케이블과 먼지 쌓인 스크린이 가득하다.
- 이번 화 장소: 중앙 제어실 / 분위기: 광기 어린, 해학적인
- 핵심 물건: 데이터 스크린 조각
- 최종보스 위스퍼 웹: 밤거리의 정보상인 '위스퍼 웹'. 낡은 코트 아래 수많은 전자기기를 숨기고 은밀하게 거래를 제안하며, 어떤 정보든 다 알고 있는 듯 능글맞게 웃는다. / 정체: 도시의 모든 디지털 노이즈와 연결된, 정보 과부하로 미쳐버린 거대한 정신적 잔해. 과거의 데이터 파편들이 뒤섞여 탄생한 광기의 정보 중독자. / 원하는 것: 세상의 모든 정보는 결국 하나로 뒤섞여야 진정한 가치를 얻는다고 믿는다. 모든 사람의 일상을 뒤죽박죽으로 만들어, 자신처럼 정보의 광기에 빠지게 하려 한다.
- 마지막 장면(twist): 위스퍼 웹이 도시의 전광판을 통해 자신의 깨진 얼굴을 확장하며 '모두가 연결되었어! 모든 비밀은 이제… 없어! 네 두려움, 네 거짓말, 네 가장 깊은 치부까지! 전부 나에게 있어! 그리고 이제… 네 것이 될 거야!'라고 외치지만, 주인공이 데이터 스크린 조각을 맞추자 그의 몸이 데이터 파편으로 흩어지며 전광판 속 얼굴도 우스꽝스럽게 일그러진다.

## 방별로 쓸 것
- prologue (3~5줄): 지난 화까지 이어진 도시의 모든 혼란은 주인공의 행동에서 비롯되었다. 낡은 전산실의 중앙 제어실은 이제 완전히 무방비 상태가 되어 그 혼란이 폭주하고 있었다. 아직 그 원인을 정확히 알지 못하는 상황이다.
- 방 1 (말 6~12줄): 1~4화의 피해가 한데 모여 도시 전체의 기능이 마비되는 상황이 터진다. 정보 브로커 에코는 그 혼란에 휩쓸릴 뻔하다가, 자신의 모든 정보가 뒤섞이는 것을 보고 정신을 차린다. 아직 원인을 모른다.
  - 마지막 줄은 목표를 향해 나서는 말
  - 카드가 맡는 것(쓰지 않음): 중앙 제어실의 폐기된 보조 전원 장치에서 2화에 전원 코드를 뽑아 충격을 받은 데이터 스크린 조각의 흔적이 발견된다.
- 방 3 (말 3~6줄): 파티는 1~4화의 행동이 겉모습만 달랐을 뿐 모두 데이터 스크린 조각을 깨뜨리는 같은 일이었다는 것을 깨닫는다. 그 뒤에 최종보스가 있었다는 사실을 인지한다.
  - 카드가 맡는 것(쓰지 않음): 중앙 제어실의 과열된 서버와 데이터 유출 출처 장치에서 3, 4화에 손상된 데이터 스크린 조각의 흔적들이 발견된다.
- 방 5 (말 3~6줄): 최종보스 위스퍼 웹이 중앙 제어실에 홀로그램처럼 처음 모습을 드러내어 '모든 정보는 깨져야 진정한 가치를 얻는다'고 말하며 자신의 동기를 밝힌다.
  - 카드가 맡는 것(쓰지 않음): 중앙 제어실의 스크린에 도시 사람들의 개인 정보가 뒤섞여 표시되며 큰 혼란이 발생한다.
- 방 7 (말 3~6줄): 파티는 위스퍼 웹의 혼란을 막기 위해 데이터 스크린 조각을 맞춰야 한다는 정답 행동을 스스로 말하고 나선다. 에코가 '모든 것을 정렬하라'는 메시지를 전한다.
  - 카드가 맡는 것(쓰지 않음): 중앙 제어실로 가는 길에 사람들이 데이터 스크린 조각을 맞추려는 주인공을 막아서며 혼란을 부추긴다.
- 방 10 (보스 룸): 최종보스 위스퍼 웹이 홀로그램으로 나타나 데이터 스크린 조각을 맞추려는 주인공을 막아선다. 싸움 후, 주인공이 데이터 스크린 조각을 맞춘다. 위스퍼 웹이 데이터 형태로 무너지고, 도시의 디지털 표지판과 개인 정보들이 모두 정상으로 돌아오는 트위스트 장면이 펼쳐진다.
  - 이 방에서 밝혀지는 복선: 위스퍼 웹이 도시의 전광판을 통해 자신의 깨진 얼굴을 확장할 때, 그 얼굴을 구성하는 숫자들이 1화 스크린에 나타났던 배열과 같았음이 드러난다.
  - dialogue(전투 전, 말 3~8줄): boss 가 막아섬
  - win_dialogue(말 3~6줄): 주인공 행동을 해내고 끝
  - lose_dialogue(말 1~3줄): 짧게
- epilogue (3~5줄): 데이터 스크린 조각이 맞춰지자, 망가졌던 도시의 디지털 표지판들이 정상으로 돌아오고 엉망이 되었던 개인 정보들도 원래대로 되돌아왔다. 낡은 전산실의 모든 스크린에는 평온한 데이터 흐름이 이어지고, 사람들의 일상도 우스꽝스러웠던 혼란을 뒤로하고 제자리를 찾았다. 모든 것이 정상으로 돌아온 해학적인 결말이었다.
